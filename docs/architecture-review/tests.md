# Test suite review: missing, misaligned, duplicated, should-be-global

Read-only audit of the repository at the working tree of 2026-11-09. Nothing was changed except this file.
Methods: scripts over `src` and `test` (file name and import matching), a route list extracted from
`apps/server/src/http`, `rg`/`grep` clusters, and one timed run of each Vitest project
(`--project node`: 235 files, 1934 tests, 1m58s wall, 161s summed file time while other agents were
also running; `--project web-browser --project ui`: 96 files, 749 tests, 25s wall, all passed).
Coverage was **not** run: `@vitest/coverage-v8` and `-istanbul` are not installed (only
`@vitest/browser-playwright`), so every "untested" below is a name/import heuristic, not line
coverage. A heuristic hit means "no test file names or imports the module"; a module can still be
exercised through a parent (noted where I checked).

## 0. Headline findings

1. **The permission matrix exists once.** There are 141 registered routes (60 GET, 48 POST, 10 PUT,
   9 PATCH, 14 DELETE); 53 writes sit under `/teams/…` or `/workspaces/…`. Only
   `instance-admin.test.ts` has an `it.each(routes)` "401 signed out, 403 member" matrix. The rest
   hand-write a few 403/404 cases per file (`rules-triage`, `settings`, `figma`, `comments`,
   `domains`), so for most write routes no test says "non-member gets 404, non-admin gets 403".
2. **The outbox guarantee is pinned for 3 of ~9 queueing services.** Rollback tests exist for
   `addComment` (comments.test.ts:87), `queueIntegrationEvent` (integration-events.test.ts:90) and
   notifications (notifications.test.ts:143). Nothing proves "queued exactly when the change commits"
   for `finalizeBuild`, `completeBuild`, `failBuild`, `requeueBuild`, `reviewBuild`, `requestReview(s)`,
   `notifyReviewRequested`, `handleGitEvents` (webhook jobs in `outbox.test.ts` only test the
   happy path).
3. **Test infrastructure is re-implemented per package.** At least 12 fake GitHub/GitLab/Slack/IdP
   hosts live in 8 places, `sha`/`png` are redefined in 9 files, 9 browser tests each write their own
   `vi.mock('#lib/auth-client.ts')` with a different shape, 48 web tests repeat
   `afterEach(restoreFetch)`, and four unrelated `json` header constants appear in server tests.
4. **Wall time is dominated by one file and one habit.** `routes-h1.browser.test.tsx` is 22 s of the
   25 s browser run (142 page opens each followed by a fixed 250 ms sleep). In the node project,
   104 of 235 files call `createTestDb()` (PGlite plus all migrations, about 0.5 s each, serial in
   the file); the six server files over 4 s are dominated by it plus sharp and real git.
5. **No shared invariants beyond one-h1.** No axe or any a11y library is installed, no test scans the
   CSS: I found 16 `outline: none` and 57 literal `border-radius: Npx` in `packages/ui/src` and
   `apps/web/src` that nothing checks (no font under 11 px: that one holds today).

### 1.2 Routes versus route tests

Extraction: 141 registered routes (`app.get/post/put/patch/delete` literals; `web-app.ts` `/*` and
the `auth.ts` catch-all excluded from the totals below). A route counts as tested when its path
pattern (params as wildcards) appears in any test string. 113 matched; the 28 misses are almost all
false negatives because tests build URLs from a `base()` helper:
`rules` (5 routes + `triage-rotation`), `triage` (4), `comments` (4), `ignore-regions/:id`
(2), `review-requests/:id/{snooze,unsnooze}`, `domains/:id` (verify, delete), `integrations/:id/targets`
and `…/links` (tested in `figma.test.ts` via `url()`/`mappingUrl()`), `PATCH …/appearance`,
`POST …/webhooks/:id/test`, `activity`. I verified by hand that each is exercised
(`rules-triage.test.ts`, `comments.test.ts`, `figma.test.ts`, `workspace-team-pages.test.ts`,
`instance-admin.test.ts`). **So route coverage is complete by existence; the gap is the permission
and isolation matrix**:

|---|---|---|
| signed-out 401 / non-member 404 / member 403 for every write | `instance-admin.test.ts:124` (one `it.each`) for `/instance/*` only | none for the 53 team/workspace writes; each file asserts a handful. `isolation.test.ts` covers GET team/build/file only |
| removed member loses access | `removed-member.test.ts` | one route sampled |

views, inbox, snooze). It also fails when a new route appears that is in neither list, which makes
the matrix self-maintaining. Needs the shared `signedInClient` below.

### 3.1 Signed-in HTTP client for server tests

Existing: `apps/server/test/support/helpers.ts` (`signIn`, `seedTenant`) and
`dashboard-fixture.ts` (`startDashboard`: `get`, `send`, cookies for acme/rival). `signIn(` appears
in 31 files / 83 calls; 14 files use `startDashboard`; the other 17 re-wrap it:

- Local request helpers redefined per file: `call(method, url, cookie, body)` in `figma.test.ts`,
  `integrations-gitlab.test.ts`, `integrations-bitbucket.test.ts`, `domains.test.ts`;
  `send(method, url, {cookie,payload})` in `comments.test.ts`, `rules-triage.test.ts`; `post(...)`
  in `github-app.test.ts`.
- `const json = { origin: ORIGIN, 'content-type': 'application/json' }` in `email-login.test.ts:22`,
  `domains.test.ts:26`, `workspace-sso.test.ts:27`, `workspace-auth.test.ts:21`; a different `json`
  in `github-app.test.ts:41` (a Response builder).
- Cookie handling: 13 `set-cookie` parses in 6 files.

Proposal: `apps/server/test/support/client.ts`

```ts
export interface Client {
  cookie: string
  get(url: string): Promise<LightMyRequestResponse>
  send(method: 'POST'|'PUT'|'PATCH'|'DELETE', url: string, body?: unknown): Promise<LightMyRequestResponse>
  as(cookie: string): Client            // same app, other identity
  anonymous: Client                     // no cookie
}
export function signedInClient(app: FastifyInstance, who: { email: string; password: string }): Promise<Client>
export const JSON_HEADERS: { origin: string; 'content-type': 'application/json' }
```

`dashboard-fixture.ts` then builds `acme`/`rival` clients with it and exposes
`fx.acme.owner.client`, `fx.addMember(role) -> Client` (member/admin/outsider) so the
permission test needs no per-file member setup.

## 4. SHOULD BE GLOBAL

### 4.1 Per-test database cost

104 of 235 node files call `createTestDb()` (108 calls): each is a fresh PGlite plus `migrate()` with
the whole migration folder. Measured in this repo: 4 sequential `createTestDb()` in one file take
about 2.1 s (first call slowest, WASM boot), so about 0.5 s each; 104 files is about 50–60 s of the
161 s summed file time, in parallel workers that also compete with sharp, git and other agents.
Options, cheapest first:

1. **Template snapshot.** In a Vitest `globalSetup` for the `node` project, create one PGlite, run
   migrations once, `dumpDataDir('none')` to a tmp file (`os.tmpdir()/circi-template.tar`), and
   `provide('templateDump', path)`. `createTestDb()` then does
   `new PGlite({ loadDataDir: new Blob([await readFile(path)]) })`, skipping `migrate()` (the slow
   part: DDL replay). Fall back to migrating when the dump is absent, so a single file still runs
   alone. Expected saving: roughly half of each call.
2. **Per-file `beforeAll`, per-test truncate.** Most files already do `beforeAll(createTestDb)`; those
   that create one per test (a few `beforeEach` users) should truncate in a `reset()` helper
   exported by `createTestDb.Result` instead of re-creating.
3. `hookTimeout`: the node project has the default 10 s; `beforeAll(createTestDb)` under 8 parallel
   workers plus other load is where "hooks timeouts" came from. Set `hookTimeout: 60_000` globally
   (it costs nothing when it passes).

### 4.2 `vitest.config.ts` duplication and defaults

Present in `vitest.config.ts`: `testTimeout: 30_000` global; `hookTimeout` only for e2e (120 s) and none
elsewhere; the two browser projects share a `.map` (good); `uiOptimizeDeps`, `webOptimizeDeps`,
`visualOptimizeDeps` are three hand-kept lists that all spread `baseUiDeps` (19 Base UI parts: a new
part used only in a test fails on first run until added). Proposals:

- Add to the root `test`: `hookTimeout: 60_000`, `expect: { poll: { timeout: 5_000, interval: 50 } }`,
  and for the browser projects `browser.expect.element` timeout 5 000 (Vitest 4:
  `test.expect.poll`; for `expect.element` it is the poll timeout). Delete the four per-test
  `timeout: 2_000/3000/4000` overrides.
- Generate `baseUiDeps` from `readdirSync('node_modules/@base-ui/react')` filtered by the directories
  `packages/ui/src` actually imports (one `grep` at config time), so the list cannot go stale.
- `setupFiles` per project: `['packages/testing/src/setup-node.ts']` (fake clock reset, `restoreAllMocks`,

## 8. Caveats

- The untested-module table is name/import matching; indirect coverage is common in this repo

  not about missing route tests.
