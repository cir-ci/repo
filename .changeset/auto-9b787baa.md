Every server setting reaches the container in both deploys. The Terraform module has one variable per setting (smtp_host, auth_oidc_issuer, s3_bucket, ...) in place of the open environment/secrets maps: a misspelled name or a half-set pair fails the plan, and a setting left null stays unset, so nothing is locked in the dashboard by accident. Secrets go in as files named by <NAME>_FILE, which the server now reads for any setting (circi admin storage migrate too), so the rest of the environment shows in plan output. database = { host, port, name, user, tls, ca_certificate } runs against your own Postgres such as Amazon RDS (verify-full, with RDS's CA bundle); passwords are URL-encoded. Caddy is the one proxy the app trusts, in Terraform and in the Compose overlay (a fixed subnet and address: CIRCI_SUBNET, CADDY_ADDRESS), instead of every private range. Route53 keys have their own sensitive variable, and the bundled Postgres's password can be rotated with ALTER USER. docker-compose.yml passes every setting (Slack, GitLab sign-in, S3 and the tuning settings never reached the server before) and .env.example names them all. The image sets HOST explicitly.
